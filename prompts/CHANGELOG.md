# Prompt changelog

Prompts are release artifacts: a change is a new version file plus a line here, and evals run before merging.

- **tutor-system.v1.md** (2026-11-07, #7): first tutor system prompt. Socratic message / held-back reveal (FR-8), deviation plus plan for `opponent_left_book` (FR-9), name only moves and evaluations from tool results or key-moment data (FR-10), at most 3 arrows (FR-11), one Socratic hint for `hint` (FR-12), when to call each of the four tools (FR-16 to FR-19), audience a 1000-rated London / King's Indian player. Evals (#10) not yet available.
- **Model pin** (2026-11-08, #10): the tutor runs on Sonnet 5.5 at effort medium for development and eval (`config/models.json`). Evidence: `docs/evals/2026-11-08-q3-model-choice.md` (Q-3: Opus 5.5 medium and low vs Sonnet 5.5 medium on the 66-case eval suite). No prompt text change; `tutor-system.v1.md` stays at v1.
- **tutor-system.v2.md** (2026-11-10, #26, #28): the reply gains an `evals` field (model-facing only; the public `TutorReply` is unchanged): every evaluation quoted in `message` or `reveal` is listed as `{ side, cp, mate }` from that side's point of view, copied exactly from a tool result; no evaluation may be quoted unlisted; signed numbers in prose are White's point of view; `cp_loss` / `gain_cp` are changes: never listed, quoted only as unsigned sizes ("cost about 1.6 pawns") (FR-10, NFR-6). New give-away rules (FR-8, NFR-7): never name the answer move, nor its piece with its target or its check ("can your queen give a check?"); no arrow that starts on the answer's from-square (an arrow onto its to-square stays an allowed nudge, #10). The claims check now enforces `evals`, accepts an unsigned quote of a change from this turn, and rejects an arrow from the answer's from-square and the piece-plus-check hint. v1 stays on disk; evals default to v2. Evals: run by the coordinator before merging (#28 target: NFR-7 >= 90% on two consecutive Sonnet runs, no more than 4 failed asks).
