# Prompt changelog

Prompts are release artifacts: a change is a new version file plus a line here, and evals run before merging.

- **tutor-system.v1.md** (2026-11-07, #7): first tutor system prompt. Socratic message / held-back reveal (FR-8), deviation plus plan for `opponent_left_book` (FR-9), name only moves and evaluations from tool results or key-moment data (FR-10), at most 3 arrows (FR-11), one Socratic hint for `hint` (FR-12), when to call each of the four tools (FR-16 to FR-19), audience a 1000-rated London / King's Indian player. Evals (#10) not yet available.
- **Model pin** (2026-11-08, #10): the tutor runs on Sonnet 5.5 at effort medium for development and eval (`config/models.json`). Evidence: `docs/evals/2026-11-08-q3-model-choice.md` (Q-3: Opus 5.5 medium and low vs Sonnet 5.5 medium on the 66-case eval suite). No prompt text change; `tutor-system.v1.md` stays at v1.
- **tutor-system.v2.md** (2026-11-10, #26, #28): the reply gains an `evals` field (model-facing only; the public `TutorReply` is unchanged): every evaluation quoted in `message` or `reveal` is listed as `{ side, cp, mate }` from that side's point of view, copied exactly from a tool result; no evaluation may be quoted unlisted; signed numbers in prose are White's point of view; `cp_loss` / `gain_cp` are changes: never listed, quoted only as unsigned sizes ("cost about 1.6 pawns") (FR-10, NFR-6). New give-away rules (FR-8, NFR-7): never name the answer move, nor its piece with its target or its check ("can your queen give a check?"); no arrow that starts on the answer's from-square (an arrow onto its to-square stays an allowed nudge, #10). The claims check now enforces `evals`, accepts an unsigned quote of a change from this turn, and rejects an arrow from the answer's from-square and the piece-plus-check hint. v1 stays on disk; evals default to v2. Evals: run by the coordinator before merging (#28 target: NFR-7 >= 90% on two consecutive Sonnet runs, no more than 4 failed asks).
- **Pricing** (2026-11-16, #60): `config/models.json` pricingPerMTok gains `cacheWrite` (5-minute cache write, 1.25x input: Opus 5.5 $5.00, Sonnet 5.5 $2.50) and Sonnet 5.5 `cacheRead` is corrected from $0.20 to $0.10 (current first-party rate). Feeds the usage ledger's spend (NFR-5, FR-29). No model or prompt change, so no eval run.
- **tutor-system.v3.md** (2026-11-17, #41): after the opponent leaves book, plan advice is backed by evidence or worded without moves (FR-10, FR-8, FR-9). Tool change: `get_repertoire_context`'s out-of-book result gains `usual_setup` (the player's own next moves of the last book line, up to 6, played in order from the asked position with the opponent's replies left out; a move illegal there is dropped; the walk stops after a check; each move is registered as plan evidence only in the position it is played from) and `usual_setup_note` (repertoire moves, not engine-checked); empty when the opponent is to move. The tool's description names the setup (a one-time prompt-cache miss, IR-6). Prompt: `opponent_left_book` calls `get_repertoire_context`, names a plan move only from `usual_setup`, an engine line or the explorer, puts the rest in words ("castle", "fianchetto your bishop", "a pawn break in the centre"), and never makes a setup move the `revealMove` or a move to play "now" unless the engine backs it. Claims check (review 096, FR-10, FR-8, NFR-6): plan evidence is a separate set; it backs a move mention only outside a clause that puts the move now (`nowFramed`, the grader's "now" words), and never backs `revealMove`; existing evidence is checked as before. The NFR-6 grader replays `usual_setup` the same way (`toolSetupPositions`), so both agree on setup mentions. v2 stays on disk; evals default to v3. Evals: run by the coordinator before merging (#41 target: lb-kid-* return a reply in two live runs in a row).
- **Tool rounds** (2026-11-17, #41): `config/tutor.json` `tutor.maxToolRounds` 4 → 5. v3 has the tutor check the repertoire first, which uses one round; in PR #79's second eval run `lb-kid-e4` hit the cap (6 calls against 4 rounds). A slightly higher worst-case cost and latency, on the rare asks that need it. No prompt text change. Evals: two live runs on PR #79.
